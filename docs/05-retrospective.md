# 05 难点、学习与下一步

以下为AI辅助工程复盘；本人投入与实际分工见[本人贡献](04-ai-usage.md)。

最难的问题是同时保持证据约束和自然表达的容忍度。引文逐字真实，不代表答案支持充分；状态标needs_clarification，也不代表实际问出了确认问题。原真实冲突案例由此被判未通过，修复后可以交付确认请求；但新口语改写仍因覆盖规则的语法边界重复失败，不能根据离线满分宣称真实可靠性已解决。

工程上把工具授权、正文映射、证据支持、适用性和预算分开，便于定位哪一层出错。源文档替换时不仅检查最终文字，还检查READ内容和ANSWER参数，动作序列是否变化单独记录；没有为迎合评审人为改变动作数量。

学习所得是先定义业务验收，再看状态与测试数量；保留失败比重写预期有价值。Mock能检验控制循环、故障与引用边界，真实模型的动作调整应看实际请求与Trace。

下一步若重新开启增强工作，应先单独定义范围与预算，集中改善控制问句、正文/声明映射和有限比较推论，再做同版真实回归；当前没有擅自继续修复或消耗剩余额度。真实稳定性、恢复链和改写泛化仍列为限制。
